# Защита инструкции: как всё устроено и что сделать

## 1. Как это работает

```
клиент                       сервер защиты                     GitHub
──────                       ─────────────                     ──────
логин+пароль  ───────────►   PBKDF2-SHA256 (600000 итераций)
                             сверка с auth/users.json
                             счётчик просмотров (5 на человека)
                             защита от перебора (8 ошибок → 15 мин)
           ◄───────────────  ключ контента, завёрнутый
                             в ключ, выведенный из пароля
расшифровка страниц          (сервер отдаёт только шифротекст)
AES-256-GCM в браузере       content/content.bin  ────────────►  GitHub Pages
```

* **Страницы инструкции больше не лежат в HTML файлом картинок.** В репозитории и в
  отданном клиенту файле — только шифротекст (`content/content.bin`), без пароля он
  бесполезен. Открыть «Просмотр кода» и вытащить страницы, как это было раньше, нельзя.
* **Пароли не публикуются.** В публичном `auth/users.json` — только соль, PBKDF2-хеш
  и завёрнутый ключ контента. Сами пароли остаются в `private/` (не публикуется).
* **Счётчик ведёт сервер.** Пересохранение файла, сброс кеша, другое устройство,
  повторная установка — просмотры не обнуляют. `developer` (владелец) — без лимита.
* **Приложение ничего не решает само.** Проверка пароля, лимит и выдача ключа — на
  сервере; без сервера инструкция не открывается вообще.

## 2. Что нужно сделать один раз

### 2.1. Включить GitHub Pages (раздача приложения)

Панель репозитория → **Settings → Pages** → Source: *Deploy from a branch* →
Branch: `main`, папка `/ (root)` → Save. Ссылка будет вида
`https://zigorminsk-debug.github.io/Arena-Instructions-/` (она уже вписана в
`app/config.js` как `link`).

### 2.2. Закрыть ветку `main` (branch protection)

Кнопка «Protect this branch» на странице репозитория или:

**через браузер:** Settings → Rules → Rulesets → New branch ruleset → Target:
`main` → включите *Restrict deletions*, *Block force pushes*, *Require a pull
request before merging* (Approvals: 0, если работаете один) → Create.

**командой** (нужен token с правами Administration — `tools/protect_branch.sh`
подскажет точную команду):

```bash
gh api -X POST repos/zigorminsk-debug/Arena-Instructions-/rulesets \
  -f name="main-protection" -f target=branch -f enforcement=active \
  -f 'conditions[ref_name][include][]=refs/heads/main' \
  -f 'rules[][type]=deletion' -f 'rules[][type]=non_fast_forward'
```

### 2.3. Поднять сервер защиты (API)

Выберите один вариант — приложение само спросит его по адресу из `app/config.js`.

#### Вариант А. Ваш собственный сервер (уже готов)

```bash
python3 server/local_server.py 8000            # или
node server/node.js 8000
```
Достаточно Python 3.8+ без зависимостей. Чтобы клиенты входили из интернета,
откройте порт/проксируйте домен (например `https://arena.csl.by` → :8000) и
пропишите адрес в `app/config.js`:
```js
api: "https://arena.csl.by",
```

#### Вариант Б. Deno Deploy — бесплатно, вход через GitHub (проще всего)

1. Зайдите на **deno.com/deploy** и нажмите *Sign in with GitHub*.
2. `python3 tools/make_server_files.py` → появится файл
   `tools/_generated/deno_single.js`.
3. Создайте проект (**Playground / New Playground**), вставьте весь текст файла,
   нажмите **Deploy**. Получите адрес вида `https://arena-protect.deno.dev`.
4. Пропишите его в `app/config.js` (`api: "https://arena-protect.deno.dev"`).
5. Счётчики хранятся в Deno KV автоматически — ничего настраивать не нужно.

#### Вариант В. Cloudflare Workers — бесплатно

1. Панель Cloudflare → **Workers & Pages → Create → Worker**, вставьте
   `tools/_generated/worker_single.js` (`python3 tools/make_server_files.py`).
2. Storage → **KV** → создайте namespace `ARENA_KV`, привяжите его к Worker
   с именем `ARENA_KV` (Settings → Variables → KV Namespace Bindings).
3. В переменных Worker задайте `APP_ORIGIN=https://zigorminsk-debug.github.io`.
4. Deploy → адрес вида `https://arena-protect.ИМЯ.workers.dev` → впишите в
   `app/config.js`.
5. Если увидите ошибку `1102` (cpu limit): на бесплатном тарифе Cloudflare
   ограничено время CPU, из-за 600000 итераций PBKDF2. Решение — платный тариф
   ($5/мес) или пересборка с меньшим числом итераций:
   `python3 arena_manual/build_secure.py --iter 100000` (защита от подбора слабее).

### 2.4. Проверить, что всё сходится

```bash
python3 server/local_server.py 8000 &            # или адрес нужного сервера
node tools/selftest_client.mjs http://127.0.0.1:8000 --owner
```
Тест повторяет путь браузера: проверка пароля → ключ → расшифровка 39 страниц.

## 3. Как выдавать доступы

1. `private/Таблица_логинов_и_паролей.xlsx` — таблица для выдачи (лист
   «Пользователи», 100 строк, пароли по 10 символов: 31^10 ≈ 49 бит).
2. Отправляйте каждому **только его строку** + ссылку на приложение.
3. Нужен ещё один человек — добавьте запись в `private/users_plain.json`
   (или запустите `gen_users.py` с нужным количеством) и пересоберите:
   `python3 arena_manual/build_secure.py`.
4. Скомпрометировали пароль — перегенерируйте: удалите запись в
   `private/users_plain.json`, запустите `python3 arena_manual/gen_users.py`
   (он доберёт недостающих) и `build_secure.py`.

Служебные аккаунты: `reader` — общий резервный (лимит 5, пароль в таблице,
лист «Служебные»), `developer` — владелец (без лимита, пароль в
`private/owner_pass.txt`).

## 4. Изменение содержимого и файлов автора

**Новые/исправленные страницы** (PDF собирается скриптами `arena_manual/`):

```bash
# 1. положите JPEG-страницы в private/pages/ (001.jpg … 039.jpg)
python3 arena_manual/build_secure.py
python3 arena_manual/build_secure.py --check
python3 tools/make_single_file.py --api https://ваш-сервер
```

**PDF/PPTX/XLSX автора** лежат в репозитории зашифрованными
(`protected/*.enc`) — открыть их можно паролем владельца:

```bash
python3 tools/vault.py unpack "protected/Инструкция_по_работе_с_AI_Arena.pdf.enc" \
       "private/Инструкция_по_работе_с_AI_Arena.pdf"
python3 tools/vault.py pack private/файл.pdf protected/файл.pdf.enc
python3 tools/vault.py list protected
```

Исходный архив со всем содержимым — `private/workspace-*.zip` (не публикуется).

> **Пароль владельца сменился.** Старый пришлось считать скомпрометированным: он
> лежал открытым в первом коммите (архив и HTML). Новый — в
> `private/owner_pass.txt`; он же используется для `protected/*.enc` и для входа
> `developer` в приложении. Внутренняя защита **уже собранных** PDF собрана со
> старым паролем (пароль читателя `12345678` не менялся) — при следующей сборке
> PDF (`python3 arena_manual/main.py`) возьмётся значение из `private/owner_pass.txt`.
> Вернуть прежний пароль: `python3 arena_manual/gen_users.py --owner-pass 'СТАРЫЙ'`,
> затем `build_secure.py` и повторная упаковка `protected/`.

## 5. Важно: очистка истории (после первой публикации паролей)

В первых коммитах `main` остались **открытые пароли и весь текст инструкции**
(архив `workspace-*.zip`, `arena_manual/users.json`, таблица XLSX). Они лежат в
истории git, даже если удалены из текущей версии. Удалить (перезапишет `main`;
сделайте это до включения branch protection):

```bash
tools/purge_history.sh        # покажет, что сделает, и потребует подтверждения
```
Скрипт удаляет из истории указанные файлы и выполняет `git push --force`.

## 6. Что защита НЕ умеет (честно)

* **Скриншоты и фото экрана** остаются возможными: приложение только прячет
  содержимое при потере фокуса и блокирует «Print Screen» в браузере.
* **Человек с действующим паролем** может один раз получить ключ контента и
  сохранить его: счётчик после этого его не удержит (он всё равно уже видел
  страницы). Полностью исключить это можно, только если сервер сам шифрует
  страницы заново под каждую сессию — см. «Дальнейшее развитие» ниже.
* **Подбор пароля офлайн** по опубликованному `auth/users.json` теоретически
  возможен: PBKDF2 600000 итераций и 10-символьные случайные пароли делают его
  очень дорогим, но абсолютной гарантии нет. Не публикуйте больше, чем нужно, и
  меняйте пароли при утечке.
* **GitHub Pages** отдаёт приложение всем — поэтому в нём и нет секретов.
* Анонимные пользователи GitHub могут создавать issues в публичных
  репозиториях — не обращайте внимания на мусорные issues, закройте их или
  отключите Issues в Settings.

Дальнейшее развитие (по желанию): хранить страницы **только** на сервере и
шифровать их заново под каждую сессию — тогда сохранённый ключ перестанет
работать, но потребуется свой сервер и больше трафика.

## 7. Если что-то не работает

| Симптом | Причина и решение |
|---|---|
| «Сервер защиты не подключён» | не задан `api` в `app/config.js` (или сервер выключен) |
| «Браузер запретил шифрование» | файл открыт локально/по HTTP; нужен HTTPS или адрес сервера |
| «Неверный логин или пароль» | сверяйтесь с таблицей; логин вводится целиком, например `user001` |
| «Слишком много неверных попыток» | подождите 15 минут (защита от перебора) |
| «Доступ завершён» | использованы все 5 просмотров — продлите в таблице и пересоберите |
| Пустая белая страница | откройте консоль браузера; чаще всего страница открыта не по HTTPS |
| Ошибка 1102 на Cloudflare | уменьшите `iter` (см. вариант В, п.5) |

Проверка состояния счётчиков на своём сервере:

```bash
ARENA_ADMIN_KEY=секрет python3 server/local_server.py 8000 &
curl -H "X-Admin-Key: секрет" http://127.0.0.1:8000/api/state
```
